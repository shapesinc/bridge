# Native capability transport

This is a default-off transport for the embedded runtime to discover and use capabilities authorized by shapes.inc. It does not import the person's Codex credentials or enable every Codex desktop capability. The backend must explicitly enable its feature flag and issue a separate, current tool-audience grant. Bridge advertises the same transport capability on macOS, Windows and Linux when a bundled executable is available. Discovery is not activation: the unchanged backend flag remains default-off, and each task still needs its current separate grant.

The integrated candidate is Bridge **0.2.11**, combining Windows ownership/cleanup source `3ec898e9df97593a07f54288e889265cf0afedac` with original-input/tool source `7ea68e94073d1853c06fa4f862a07f949059cbe2`. The separate 0.2.10 release, tag and artifacts are preserved; this changed runtime cannot be labeled 0.2.10. No version/tag is reserved by this source update. Candidate source, native publication, standalone publication and feature activation remain separate steps under the [release sequence](../README.md#releasing-the-macos-app).

## Composable contracts

- `shapes_discover({query?, cursor?, limit?})` finds currently authorized capabilities. Discovery does not grant permission to act.
- `shapes_describe({capability_id})` returns the current exact schema and its revision.
- `shapes_call({capability_id, schema_revision, arguments})` requests one operation. Bridge injects a deterministic UUIDv5 operation ID derived from the granted run and actual native thread, turn and call IDs. Transport never retries a mutation automatically.
- `shapes_read_operation({operation_id})` reads an operation's durable outcome. Omitting the ID lists recent receipts in the current authorized session, with optional cursor and limit, so a lost process does not require repeating an action. A final page can have `next_cursor: null`.
- `shapes_cancel_operation({operation_id})` requests cancellation. It does not imply that an already delivered action was undone.

Each request uses `POST /bridge/native-tools/{discover,describe,call,read,cancel}` at the inference gateway's origin. Its common envelope carries session, scope, request and run IDs from the trusted grant, actual native thread/turn/call IDs, and action arguments. The separate bearer token is retained only in the supervisor environment. It is excluded from the runtime/MCP environment, persisted job request, model responses and ordinary logs. The backend owns fresh actor, room, source, device, connection, capability, consent and funding checks; a caller cannot select those authorities in model arguments.

Results are bounded JSON receipts with `success`, `result`, or an error. Call/read/cancel receipts identify the operation and one of `running`, `completed`, `failed`, `cancelled` or `outcome_unknown`. A timeout, malformed response or oversized response preserves an unknown receipt, never a success claim. Read/list can recover earlier runs in the same backend-authorized session. Backend turn closure must fence outstanding operations, including when Bridge cannot send cleanup because its process or grant has expired.

## Runtime boundary

Pinned Codex 0.166 restores dynamic app-server tools from the original thread and ignores attempted replacement at resume. Therefore this adapter uses stdio MCP instead. Actual runtime replay verifies that an existing native thread acquires tools when enabled and loses them when disabled, without forking its conversation.

The MCP subprocess receives a private local endpoint, non-secret run ID and path to a per-job IPC credential. It never receives the backend tool bearer. `private-channel` separates listener creation, authenticated connection and disposal from the tool protocol. Unix uses an atomic 0700 directory and 0600 socket/credential; Windows uses a unique named pipe and credential beneath the existing current-user/SYSTEM-only state directory. Both peers prove the secret with fresh nonce/challenge HMACs bound to protocol and run before request-first application traffic. Secrets never cross the channel. Authentication has a 512-byte message bound, two-second deadline and four-connection cap. The frontend's startup is required and cannot finish before authentication. Unauthenticated, stale-scope, replayed and rogue-server traffic never reaches capability dispatch.

The supervisor validates native metadata and proxies requests. The frontend computes the same operation ID before dispatch and can return it on broker loss. Recent-receipt listing handles complete supervisor/runtime loss before a receipt reaches history. Windows retains enclosing Job ownership and native empty-Job proof; Unix retains existing process ownership. Normal closure stops the proxy, drains authenticated/pending sockets and removes only its private directory. Broker cleanup failure cannot skip runtime closure: both settle, and uncertainty persists as a failed receipt. Abrupt supervisor loss may leave inert private state for explicit owned-fixture cleanup; it is not a successful cancellation claim.

Only the five named tools have explicit `approval_mode="approve"` overrides, with the same five-name `enabled_tools` allowlist on this isolated MCP server. Backend action-specific authorization remains required. Existing native approval/question handling, other MCP servers, global approval policy and sandbox are unchanged. Mutation tools are not falsely marked read-only. This MCP server is required to connect before a granted task starts.

Limits: 256-character discovery queries, 160-character capability IDs, 500-character cursors, 16 KiB JSON arguments, 32 KiB backend response, eight pending requests, 64 outstanding operations, four broker connections, 15-second HTTP deadline, and a two-second total best-effort cleanup deadline with at most four concurrent cancellations. The existing 256 KiB inference gateway envelope and funding controls remain unchanged. Only text receipts are supported in this slice; media and paid nested capability services need their own reviewed admission.

## Verification and cost

Upstream 0.2.10 Bridge HTTP, supervisor and pinned-runtime replay on macOS used only loopback fake inference/capability services. It exercises browser and document compositions, receipt recovery, disabled/enabled resume, Stop, and SIGKILL after admission followed by same-thread receipt listing/read without mutation redispatch. Linux retains the Unix transport; an actual pinned-runtime replay on Linux is not included in this evidence. Separate focused tests cover metadata forgery, extra tools, credential handling, result limits, cancellation, socket loss and unsupported-platform advertising. The captured provider packets are replayed through the real ASGI inference route and Redis reservation/settlement ledger with a fake provider and synthetic wallet.

These are simulations of provider and connected-service effects. They do not establish live browser/app permissions, provider payment, or complete product readiness. Integration with original-input/image changes and the affected UI still requires verification before rollout.

The actual deferred five-tool metadata is 2,869 UTF-8 bytes, approximately 604 tokens using the locally available `cl100k_base` estimator, not the billed Astra tokenizer. No new schemas or server instructions appeared directly in the initial provider prompt; metadata enters when the model discovers it and is then retained in later history. Conservatively retaining those 604 tokens for ten requests per task at 100 tasks/day, 20% retries, no caching and $10/M input tokens costs about $7.25/day. It is included in the broader illustrative 2,000-added-token scenario, not additional to it.

Traffic is unknown. At 100 tasks/day, 2,000 added tokens retained over ten requests plus two additional continuations of 20,000 input/500 output tokens, with 20% retries, no caching, $10/M input and $50/M output, the total illustrative increase is $78/day. Half/double that workload is $39–156/day; retaining 16,000 added context tokens makes the same 100-task scenario $246/day. No classifiers or embeddings are added here. Tool-provider fees and images are excluded because this slice does not admit them. Default-off production activation adds $0/day; local fake-provider evaluations incur no provider charges.

Run the focused Node tests and `scripts/replay-native-tools.js` with `SHAPES_BUNDLED_CODEX_BINARY`. Optional `SHAPES_NATIVE_TOOLS_REPORT` and `SHAPES_NATIVE_TOOLS_CAPTURE` write new private files with mode 0600; captures contain runtime context and must never be committed. Backend packet replay uses `BRIDGE_CODEX_CAPTURE` and `tests/test_bridge_harness.py::test_opt_in_pinned_codex_capture_through_native_gateway`.


## Integrated parity verification and cost

The available-runtime contract is tested across darwin/win32/linux; missing binaries disable session input and tool proxy on every host. Actual local socket/stdin/HTTP tests cover mutual authentication, wrong credential/scope, replay, rogue server, partial/oversized messages, cancellation, broker loss and independent cleanup. Supervisor fixtures use real durable state with simulated cleanup failures. Windows CI also executes these tests on named pipes and replays the official checksum-pinned app-server with fake loopback inference/capability services. The new combined runtime's Windows results and both installed desktop flows must be recorded before readiness; upstream tests do not establish them. No live provider charge or feature activation is part of these fixtures.

At identical task/model packets, the Windows IPC adapter and capability discovery add **$0/day**: no new schema, prompt, model call, classifier, embedding or automatic work. The inherited original-input/context behavior has nonzero context cost and is accounted for in [bundled-session integration costs](bundled-sessions.md#integrated-windows-input-cost-and-acceptance). The existing proxy scenario above remains $0 while disabled, or $78/day per 100 explicitly enabled tasks under its stated assumptions; it is not an implicit launch authorization. No grant, approval, permission, funding or flag default changes here.

The combined source passed a serialized macOS Node run (336 passed, 24 Windows/systemd skips) and three additional cleanup regression tests. A fresh checksum/cache verification of official macOS arm64 Codex 0.166 preceded actual replays: 15 input/session compositions and nine tool/receipt compositions passed with loopback simulated services. Original text/image history, CSV and HTML/file execution, read-only refusal, overflow, Stop, receipt recovery and dynamic tool removal all used the same runtime contracts. Supervisor-only loss stopped all three observed descendants without fixture termination. Every replay awaited owned leaders and listeners before deleting its temporary state. This is real runtime execution with simulated service/model responses, not installed-app or live provider acceptance. Windows CI must independently pass the same replay, including mandatory automatic Job descendant exit.
