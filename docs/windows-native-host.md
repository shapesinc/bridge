# Windows app-owned computer connection

The Windows desktop app composes the same embedded-controller operations as the macOS app. The controller retains pairing ownership, cancellation receipts, account membership, device pause/revocation, local task idempotency, provider funding and existing gateway budget checks. No AI calls, prompts, classifier work or retries are added by this port: incremental provider spend for existing traffic is **$0/day**. Additional adoption may increase existing metered task usage; that traffic is not measured by this change and is not a new per-request cost.

## Primitive contracts

- `spawnOwned(executable, args, options)` launches an installed executable as one owned process tree. POSIX retains existing process groups. Windows uses the bundled `shapes.inc Bridge Job.exe`, which joins a non-breakaway Job before creating its child. Closing or killing the wrapper closes the only Job handle and terminates descendants. The wrapper watches its exact launching parent handle unless the caller selects an independent durable supervisor. Arguments remain an array, with a separate, explicitly selected `cmd` command-string transport. It never discovers processes by name or trusts saved PIDs to authorize cleanup.
- `createEmbeddedHost({controller, token, version, endpoint})` owns one controller and one authenticated foreground attachment. Requests remain the existing bounded embedded protocol. A lost attachment invokes `detach`, cancelling unfinished setup while preserving an established connection. Only disposal of the durable host terminates that controller and its runtime. The 256-bit attachment capability is stored in the app's private ACL-protected state directory and never reaches a web document.
- `resumeSavedConnection()` is a private host lifecycle operation, unavailable over RPC. It resumes only an established device with `resume_on_startup:true`, a matching API and device credential, no pause/revocation, and no unfinished pairing. It never restores the foreground account or permits account-bound actions. The existing daemon heartbeat authenticates the device credential before the server publishes the fresh endpoint. `backgroundActive()` supplies only the owned runtime's liveness for idle retirement; it does not imply verified account identity or online readiness.
- `commandShell(cmd, shell)` chooses a shell transport independently of execution. Windows PowerShell uses a private UTF-8 script with BOM, preserving multiline and non-ASCII commands without a second command parser. `cmd` is explicitly selected and accepts one line. A command timeout/cancellation ends the exact owned tree. Script files are removed after completion.
- Local task start, status, events, response, cancellation and retry contracts are unchanged. Windows native provider executables and bundled `codex-app-server.exe` now use owned process trees. Personal sign-in opens the provider's official login command in its own console only after the native app's confirmation; no credential is returned over the bridge.

The installed native app registers an app-specific, least-privilege Task Scheduler task under the signed-in interactive Windows user. Its Job wrapper launches `bin/embedded-host.js` with fixed installed paths and a dedicated state directory. A foreground quit closes only its authenticated attachment. Host replacement first probes the packaged version and retires only the exact old task before forwarding mutations. After logon/reboot, a fresh host can resume a previously approved device through its persisted device credential. This authority is separate from the foreground account: status hides device details until the native app independently verifies the current signed-in account and device membership.

Completed native approval or verified owner resume enables the durable startup marker. Sign-out, failed account verification, a different account, or removed membership clears it before stopping the runtime. Explicit Disconnect persists pause. Earlier saved configurations without the marker need one successful verified foreground attachment after upgrade; the host does not infer startup permission from a saved owner string. Foreground reopen retains its existing verified-owner behavior. An invalid or revoked device credential is marked revoked on disk and cannot restart; temporary heartbeat failures keep retrying with the same credential and no new pairing. Device credentials currently have no time-based expiry in the backend; pairing expiry and foreground authentication failure are distinct boundaries.

As on macOS, initial status/account requests can register an idle helper before Connect. Without an eligible saved approval, that does not start computer access. With no foreground attachment or active owned runtime, a disconnected or paused controller retires its idle process tree and exits successfully; its scheduler registration remains for demand startup. An established connection remains alive after foreground Quit. The current macOS LaunchAgent is demand launched through its Mach service; this Windows startup fix does not establish macOS OS-sign-in resume or add a macOS launch trigger.

Package layout is `computer-connection/{manifest.json,node.exe,shapes.inc Bridge Job.exe,shapes.inc Bridge Computer.exe,cloudflared.exe,bridge/{bin,src,assets,package.json},codex/x64/**}`. `manifest.json.version` identifies the packaged app/helper revision. Windows binaries must be compiled from the pinned source and the complete pinned official Codex Windows package must be included; startup must not download executable code.

The standalone npm/CLI distribution also includes `scripts/windows/JobHost.cs`. Its Windows installer compiles that source with the installed .NET Framework into the existing private state directory, keyed by the source SHA-256; foreground use can prepare the same cached helper. Updates keep old helper files intact while earlier jobs may still execute them. No network download or elevated process is needed for compilation. A signed desktop runtime with missing packaged resources fails closed and never uses this compilation fallback.

## Compositions

1. Initial native setup: independent current-session verification → native Connect confirmation → begin pairing → existing authenticated web approval → refreshed verified device list → complete → status. Cancel, navigation and app quit end the exact unfinished attempt.
2. Reopen: attach to the same durable host → independently verify the same account → read status and existing task events. The existing device and task continue after foreground quit. A different account or removed membership suspends access through the existing controller.
3. Explicit pause: disconnect → close/reopen foreground app → verify account → status remains paused. Resuming is an explicit native-approved attempt; no new pairing or funding source is invented.
4. Local work: choose a workspace independently → grant it through the existing authenticated web flow → start a funded built-in or personal-provider task → observe events/respond/cancel through existing primitives. Provider login is separate from discovery and execution.
5. OS sign-in: launch registered host → check saved startup eligibility → start owned daemon → authenticate existing device credential on heartbeat → publish fresh endpoint. No web-account authority is reconstructed. Later foreground verification, explicit pause or server revocation reuse the same independent primitives.

## Verification and remaining release gates

Portable regression checks exercise native-host account/document races, bounded independent account verification, fixed operation envelopes, lost acknowledgements, private pipe authentication, detach/reconnect/pause, and unchanged POSIX cleanup. Existing local-agent/RPC tests use simulated provider executables and do not make inference calls. Windows CI compiles the native Job helper and exercises actual Windows argv/stdin/stdout, child/grandchild termination, and abrupt-parent cleanup. Computer-helper tests use a throwaway native window.

`test/embedded-startup-runtime.test.js` uses a real durable host, owned child daemon, private persisted JSON and authenticated HTTP computer endpoint. It checks fresh-host resume and reopen, hidden foreground authority, credential rejection/revocation, outage recovery, expired approval, no-marker migration, pause and persisted account invalidation. The remote credential authority, tunnel and OS probes are local simulations; this is runtime-boundary evidence, not production sign-in or Task Scheduler logon acceptance. The same suite runs with the real Job helper on Windows CI.

**NO-GO until final Windows acceptance:** the exact signed installed candidate still needs interactive current-account sign-in, live pairing/tunnel readiness, screen/input operations, personal-provider sign-in, built-in budget failures, account switch/removal, cancel/retry, foreground close/Quit/reopen, logon, update and uninstall checks. A portable test pass or cross-compilation is not evidence for those behaviors. Live provider/payment behavior must be distinguished from simulations.

Successful ordinary shell commands retain their existing ability to start background processes. Their per-command Job releases kill-on-close only when the shell exits successfully; a timeout or cancellation of a pending command still terminates its tree. The native host's enclosing Job keeps ownership of these background processes and terminates them when the runtime is stopped. Durable task supervisors independently outlive a short CLI start call while retaining the same enclosing native ownership.

The PowerShell script transport was adapted from bielmorales's concurrent [Bridge #31](https://github.com/shapesinc/bridge/pull/31), commit `77da236`. This branch substitutes kernel Job ownership for that draft's PID-based command-tree termination and preserves the existing command receipt shape. It does not merge or claim readiness for the draft's broader recovery work; reconcile shared files before integrating either branch.
